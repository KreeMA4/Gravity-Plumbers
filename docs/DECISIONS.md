# Decisions log

One line per decision: what was decided, and why.

- **No Godot binary was run while building this.** The official Godot 4.6 Linux build downloaded fine, but this environment's permission rules blocked running it. Instead, every script is checked with `gdtoolkit` (a GDScript parser) plus `tools/validate_project.py`. Runtime behaviour is listed under UNVERIFIED in STATUS.md.
- **Input actions are registered in code** (`scripts/core/input_setup.gd`), not in project.godot. Why: the input-map text format is fiddly and easy to break by hand. The validator reads the same list.
- **Screens are built in code and swapped by GameState** under the single `scenes/main.tscn`, instead of `change_scene_to_file`. Why: there is only one tiny .tscn, nothing to break, and the autoloads stay simple.
- **Screen ids are added to GameState.SCREENS milestone by milestone.** Menu buttons for screens that don't exist yet are greyed out and marked "(soon)", so every milestone runs without errors.
- **Autoload order:** Tuning, SaveData, GameState, Quality, GravityManager, AudioManager, NetManager. Each one only uses autoloads listed before it in `_ready`.
- **Logging:** Godot's file logging is on (`user://logs/godot.log`), and `GameLog` also writes `user://logs/game.log`. Game warnings are plain prints, so a healthy session shows zero engine warnings.
- **Physics interpolation is on.** Cameras update in `_process` from `get_global_transform_interpolated()` and have interpolation turned off themselves. Teleports call `reset_physics_interpolation()`.
- **Only the latest milestone zip is kept** in `dist/`, so the git history doesn't fill up with copies.
- **Window:** 1920x1080 base with `canvas_items` stretch and `expand` aspect, so UI sizes are in "1080p pixels" and layouts widen for 21:9 screens. Orientation is sensor-landscape.
- **"11 bodies"** means pelvis, chest, head, 2 upper arms, 2 forearm+hand, 2 thighs and 2 shin+foot, as the brief lists them. The simple rig (7 bodies) merges each whole arm and each whole leg.
- **Muscles change angular velocity directly** (a velocity-based PD controller) instead of applying torques. Why: it doesn't depend on mass or inertia, so light and heavy limbs tune the same and the rig is much harder to explode. A fraction of the change is pushed back into the parent body.
- **A hover spring on the pelvis does the standing**, with the legs mostly animating. This is the standard trick that makes active ragdolls controllable. A ray from the pelvis along -local up stands in for the "foot rays".
- **No self-collision inside one plumber.** Every pair of parts gets a collision exception, for stability.
- **The mustache is cosmetic springs, not physics bodies.** It looks the same, costs nothing and never needs syncing.
- **Grab hands landed in M3** (the brief has them in M4), because bracing during gravity shifts needs them. M4 adds the tools.
- **Touch controls take touches in `_input`.** The top 16% of the screen is left alone so HUD buttons stay tappable.
- **"A single player can never hard-fail."** In solo, the sludge meter is capped at 95% and the timer never fails you. Fewer stars is the only penalty. Co-op can flood.
- **Two-player valves and switches work solo:** a two-player valve turns at half speed with one player, and a two-player switch needs only one pull. Same code, but solo stays completable.
- **Gameplay objects share one tiny network state format** (`LevelObject.get_net_state()`). The host broadcasts them a few times a second with the sludge and the work orders, instead of a custom message per object.
- **Pooled goo blobs are disabled with `process_mode = DISABLED`**, which takes them out of the physics space, instead of being freed and recreated.
- **Results screen landed in M5** so the test level can finish; M6 adds the hub and Level 1.
- **Every RPC lives on the NetManager autoload** (plus GravityManager's two). Level nodes are built in code, so their paths would be fragile; an autoload's path never changes.
- **Puppets use the host's rig type** (sent with start_level), so snapshot part lists always line up, even when a client's own quality setting is "simple ragdoll".
- **Network ids for props = build order.** Every peer builds the level from the same data in the same order, so nothing has to be negotiated.
- **"Back to Lobby" after a level** returns everyone to the lobby screen. The hub is also playable online, as a lobby level choice.
- **The fake remote bot** feeds its input through the real packet encoder and the simulated lag and loss queue, so one phone can test the network path.
- **Music looping is set in code** (`AudioManager._make_loop`) instead of in `.import` files, so the WAVs work with Godot's default import settings and nothing fragile needs committing.
- **All audio is generated by `tools/make_audio.py` with the standard library only**, and the WAVs are committed (3.3 MB).
- **Translation:** UI text is written in English in code. Godot auto-translates Control and Label3D text, using the English text as the key, when a translation is registered. `tools/extract_strings.py` collects every string into the single file `assets/lang/strings.csv` for translators.
- **Static batching:** after a level is built, static meshes are merged into one mesh per material (`LevelBatcher`), keeping rooms to a handful of draw calls. Interactive objects keep their own meshes.
- **Decorative motion (valves, levers, clogs, spinners, ducks) updates on physics ticks**, so physics interpolation smooths it. Purely visual screens (menu backdrop, customise turntable) turn interpolation off and animate in `_process`.
- **Hit-stop is solo-only.** Changing `Engine.time_scale` on a host would slow the whole session for everyone.
- **CI builds the APK on GitHub Actions** (`.github/workflows/android-apk.yml`), with Godot 4.6-stable plus the matching templates, JDK 17 and Android build-tools 35. A fresh debug keystore is made on every run. `tools/ci/run_godot.py` fails a step on any `SCRIPT ERROR` / `ERROR:` line or a missing "proof it ran" line, because Godot often exits 0 even after errors. `tools/ci/verify_apk.sh` checks the signature, arm64, permissions and landscape orientation.
- **Tests are now included in the export** (the exclude filter used to drop `tests/*`), because the in-game "Run Tests" screen needs those scripts.
- **CI boot flags** `--screen=`, `--level=`, `--ci-screenshot=` and `--ci-frames=` in `main.gd` let the smoke tests open every screen and level. They are test hooks only; gameplay is unchanged.
- **Clean shutdown:** `GameState.quit_game()` stops all audio and gives Godot's audio thread a moment to release sounds before quitting, so no resources are reported "in use at exit". CI smoke tests quit through it (`--ci-quit-frames=N`); `--quit-after` remains only as a hang guard.
- **One narrowly-scoped CI exception:** if every object leaked at quit is an `AudioStreamPlayback*` (a known Godot shutdown race), the run reports it as a NOTE rather than a failure. Any other leaked type, any script error, or a leak without details still fails. The clean shutdown above means this hasn't been needed since.
- **Launcher check reads the manifest**, because Godot 4.6 puts MAIN + LAUNCHER on an `<activity-alias>` (`GodotAppLauncher`), which `aapt dump badging` doesn't report as "launchable-activity".
- **Movement joystick bug (Android): root cause.** `TouchControls` (a Control inside a CanvasLayer) called `set_anchors_preset(PRESET_FULL_RECT)` in `_ready`. On a node already in the tree that keeps the current (zero) rect, so the layer's `size` stayed about (0,0) on device. As a result, the joystick home was computed near the top-left corner, the "left zone" test used a zero width, and the joystick ring was only drawn while a finger was down, and then faintly. Fix: `set_anchors_and_offsets_preset()`. The joystick is now a fixed, always-visible stick at the bottom-left of the safe area (bottom-right when left-handed). If a touch starts elsewhere in the lower-left zone, the stick re-centres under the thumb and returns home on release. The joystick maths live in `JoystickMath` (unit-tested). `tests/touch_e2e_test.gd` drives real touch events through the real game in CI.
- **Every CI APK is stamped with its GitHub Actions run number.** `tools/ci/stamp_build.py` runs before any test, in the CI checkout only, and is never committed. It sets four things:
  - the file and artifact name, `GravityPlumbers-Android-Debug-Run<N>.apk`;
  - the Android `versionName` (`<version>-run<N>`);
  - the `versionCode` (`N`; run numbers only grow, so each APK installs over the last);
  - `scripts/core/build_info.gd`, shown on the main menu, in the debug overlay and in the startup log.

  Export starts from an empty `build/`, and the APK must be newer than a marker made just before export. `verify_apk.sh` checks the APK's version is this run's. After upload, the artifact is downloaded again and its contents, SHA-256 and version are checked. The SHA-256 goes in the run summary, an annotation, `BUILD_INFO.txt` and `<apk>.sha256`. Builds made outside CI show "local build".
- **Picking up is separate from grabbing.** Root cause of accidental pickups: holding Grab R equipped any tool that touched the palm sphere, and tools had the highest grab score. So reaching for a pipe or wall near the tool rack (or holding Grab while walking past) grabbed the tool. Now there are four separate actions:
  - **Pick up:** only the new Interact input does this (`PlumberInput.INTERACT`, bit 256, sent in the input packet's spare byte; C key, RB or d-pad down, and a contextual touch button).
  - **Hold / carry:** tools equip into the right hand; pipe pieces and goo canisters are carried, locked to the right hand, until Interact again (DROP).
  - **Grab (Grab L / R):** clings to surfaces, crates and teammates, and ignores the `pickups` group.
  - **Use:** the held tool.

  `Interaction.find()` picks the best target: switches and stations first, then the item you face (closest wins between equals), then DROP. It checks range (`Tuning.PICKUP_RANGE`), angle (`PICKUP_MIN_DOT`) and line of sight. The same query runs on the host (to act) and on each device (to show the prompt), using only state every peer has. The snapshot carries a "right hand full" flag (`F_HAND_FULL`) so clients know too.
- **Carried pipe pieces snap into their port without lining up.** A carried piece is held crossways and can't be twisted, so bringing it to the port is enough. A loose piece still has to be aligned.
- **Walk animation: planted feet instead of swinging legs.** Root cause of the floating look: the hover spring held the pelvis at a fixed height while the hips only swung back and forth. A swinging straight leg lifts its foot, so both feet were off the floor mid-stride and the body slid along. `Gait` (pure maths, unit-tested) gives each leg a stance/swing cycle. The cadence is matched to the measured speed, so a planted foot moves back at exactly body speed (no skating). Two-bone IK puts the foot on the floor, and the pelvis rides only as high as the stance leg reaches, which makes the walk bob. On top of that: a walk-to-run blend (flight phase, lean, bent elbows), hip-roll weight shift, idle breathing, jump tuck, falling reach and landing squash. All of these are only muscle targets for the same physics ragdoll, so balance loss, ragdoll, recovery, grabs and wall/ceiling walking are untouched.
- **Exposure: Linear tone mapping with a lighting budget.** Root causes of the washed-out look:
  - The toon rim was unlit emission on every surface, so floors and walls at grazing angles glowed.
  - Shadowed pixels still got half of the middle band.
  - Walls were 0.85-1.0 albedo under strong ambient plus a full-band sun.
  - Filmic with white = 1 clipped everything above 1 to white.
  - Lamps were banded hot spots.

  The fixes:
  - The rim is now a lit-side lighting term, and 0 on level surfaces.
  - Shadows fall to the shadow band.
  - Lamps give soft pools of light.
  - Lighting budget: ambient 0.5, sun 0.8, lamps 0.4. Palettes stay under ~0.85.
  - Floors have world-space tiles and walls have panels (shader pattern, batching-safe).
  - Every level has its own palette, with clear floor/wall/ceiling/trim separation.
  - Soft sun shadows are on from Medium quality up.

  CI prints near-white / clipped / saturation / contrast numbers for every screenshot.
- **Dynamic props use continuous collision detection.** The soak test caught a crate leaving the room at 24 m/s after a sideways gravity shift. Falling the width of a room reaches about 20 m/s, which is one 0.4 m wall per physics tick, so it tunnelled through. `Geo.dynamic_box` now sets `continuous_cd`.
